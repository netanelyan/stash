# Stash

A desktop editor for LLM prompts. Your prompts are plain Markdown files in a
folder you own; Stash is just a good editor for them. Single user, offline, no
accounts, no telemetry, no network calls of any kind.

- Autosave, always. There is no save dialog, and Ctrl+S only means "now".
- Tabs, a file tree, tags, fuzzy quick open, full text search, version history.
- `{{variables}}` with defaults, filled in from a panel and copied to the clipboard.
- Global Ctrl+Alt+S quick capture from anywhere in Windows.

## Running it

```sh
npm install
npm run dev      # Vite dev server + Electron, renderer hot reloads
```

If `npm install` leaves `node_modules/electron/dist` missing (npm may block a
package's install script and print a warning about it), fetch the Electron
binary once with:

```sh
node node_modules/electron/install.js
```

Other scripts:

| Script | What it does |
|---|---|
| `npm run dev` | Vite dev server plus Electron pointed at it |
| `npm run build` | Build the icon, the renderer (`dist/`) and the preload bundle (`dist-electron/`) |
| `npm start` | Build, then launch Electron against the built files |
| `npm run dist` | Build, then produce the NSIS installer in `release/` |
| `npm run icon` | Regenerate `build/icon.ico` only |

Changing anything under `electron/` means restarting `npm run dev`; renderer
changes hot reload.

## Building the installer

```sh
npm run dist
```

Produces `release/Stash Setup <version>.exe`: a per-user NSIS installer that
lets you choose the install directory and creates Start menu and desktop
shortcuts. `release/win-unpacked/Stash.exe` is the same build, unpackaged.

The app icon is `build/icon.ico`, generated by `scripts/make-icon.cjs` (a plain
blue "S" placeholder at 16/32/48/256px). Drop a real `.ico` in its place and
remove the `make-icon.cjs` step from the `build` script if you'd rather keep
your own.

## Where your prompts live

The vault is a normal folder: `Stash` inside your Documents folder. Stash asks
Windows where Documents actually is, so if you have moved it into OneDrive the
vault goes there too (`C:\Users\<you>\OneDrive\Documents\Stash`) rather than
into a stray unsynced `C:\Users\<you>\Documents`.

Created on first run along with an `Inbox` subfolder. Change it from the gear
icon at the top of the sidebar (Ctrl+B) -> **Change vault folder...**. The chosen
path is remembered in `config.json` under Electron's userData directory
(`%APPDATA%\stash\config.json`), together with your open tabs, cursor positions,
expanded folders, editor font size and last used variable values.

Subfolders in the vault are collections, nested as deeply as you like. Two
folders are Stash's own bookkeeping and are never shown in the tree:

```
<vault>/.stash/history/<id>/<timestamp>.md   version snapshots
<vault>/.stash/trash/                        deleted prompts
```

Deleting a prompt moves it to `.stash/trash` with a timestamp suffix; nothing is
unlinked by the app. The undo toast puts it straight back.

The vault is safe to keep in git, Dropbox or OneDrive. Stash watches the folder
and picks up changes made by anything else.

## Using it on two machines

Prompts are just files, so syncing is the folder's job, not the app's. Put the
vault somewhere that already syncs (OneDrive, Dropbox, a git repo) and point
every machine at it:

1. On each machine, install Stash.
2. Open the sidebar (Ctrl+B) -> gear -> **Change vault folder...** and choose
   the same synced folder. If both machines have Documents redirected into the
   same OneDrive account, the default is already that folder and there is
   nothing to change.

Set the folder on each machine rather than assuming the path matches: Google
Drive's letter (`G:` here) and your Windows username can both differ between
machines.

What syncs and what does not:

- **Syncs:** every prompt, plus `.stash/history` (snapshots are keyed on the
  prompt `id`, which survives renames and moves) and `.stash/trash`.
- **Stays local:** `config.json` in `%APPDATA%\stash` - open tabs, cursor
  positions, window size, editor font size and remembered variable values are
  per machine on purpose, so the two machines do not fight over them.

Three things to know:

- The sync client has to be running and signed in. Stash writes plain files and
  does nothing clever to help it along.
- Editing the *same* prompt on both machines at once is the one way to get hurt:
  autosave writes often, so the sync client resolves it by leaving a second file
  next to yours (`untitled-LAPTOP.md` or similar), which then shows up in the
  tree as a separate prompt. Let one machine finish and sync before picking the
  same prompt up on the other.
- Keep the vault available offline. Stash reads every prompt at startup to
  build its index, and cloud-only placeholder files make that slow, or
  impossible with no connection. On OneDrive that is right-click -> **Always
  keep on this device**; on Google Drive for desktop in streaming mode it is
  right-click -> **Offline access** -> **Available offline**.

### Google Drive specifically

Google Drive for desktop in streaming mode mounts a virtual drive (`G:\My
Drive`), which is not a normal NTFS volume, so it is worth saying that the two
filesystem behaviours Stash depends on were checked there and both hold:
`rename` over an existing file is honoured (autosave stays atomic) and
`fs.watch` with `{ recursive: true }` fires, so a prompt arriving from the other
machine shows up in the tree without a restart. Mirror mode is a plain local
folder and is fine too.

## File format

One prompt is one Markdown file with YAML frontmatter:

```markdown
---
id: 01JQ8F3K2M9XZ
title: Code review - security pass
tags: [coding, review, security]
created: 2026-09-22T10:04:11.000Z
updated: 2026-09-22T14:31:02.000Z
---

You are reviewing {{language}} code for security issues.

Focus on: {{focus|injection, auth, secrets}}
```

- **`id`** is generated once and never changes, even when the file is renamed or
  moved. Version history is keyed on it.
- **`title`** is what you see everywhere. The filename is derived from it
  (slugified, `.md`) when you create or rename a prompt, but the frontmatter
  title wins for display.
- **`tags`** is a plain YAML list.
- **`created` / `updated`** are ISO timestamps; `updated` is refreshed on every
  save.

A file with missing or malformed frontmatter is not a problem and is never
rewritten destructively: the whole file is treated as the body, the title comes
from the filename, and Stash only starts writing a frontmatter header once you
edit the title or tags.

### Variables

`{{name}}` and `{{name|default value}}` anywhere in the body. They are
highlighted in the editor, listed in the **Variables** panel with an input each
(prefilled with the default), and remembered per prompt between sessions.
**Copy filled** substitutes them; **Copy raw** copies the body verbatim.

## Keyboard shortcuts

| Shortcut | Action |
|---|---|
| Ctrl+P | Quick open (fuzzy over title and path) |
| Ctrl+Shift+F | Full text search across the vault |
| Ctrl+N | New prompt |
| Ctrl+Shift+N | New folder |
| Ctrl+W | Close tab |
| Ctrl+Tab / Ctrl+Shift+Tab | Next / previous tab |
| Ctrl+1..9 | Jump to tab by index |
| Ctrl+B | Toggle sidebar overlay |
| Ctrl+J | Toggle right panel |
| Ctrl+Shift+C | Copy with variables filled |
| Ctrl+Shift+V | Copy raw |
| Ctrl+F | Find in current prompt |
| Ctrl+S | Force save now |
| Ctrl+= / Ctrl+- | Editor font size |
| Ctrl+Alt+S | Quick capture (works system wide) |
| Esc | Dismiss context menu, modal, sidebar, then panel |

Middle-click a tab to close it; drag tabs to reorder them; drag a prompt onto a
folder in the tree to move it.

If another application already owns Ctrl+Alt+S, Stash says so in Settings and
lets you record a different combination.

## Layout notes

- Closing the window parks Stash in the tray. The tray menu has **Show Stash**,
  **Quick capture** and **Quit**; only Quit actually exits.
- The tab bar is the title bar. Double-click the empty strip to maximize.
- The sidebar is an overlay, not a column: the editor stays full width.
- The status bar shows the file path, character count, a rough token estimate
  (characters / 4) and the save state.

## Layout of the source

```
electron/        main process: window, tray, IPC, all filesystem work
  channels.cjs   every IPC channel name, in one place
  vault.cjs      path containment, atomic writes, index, history, trash
  frontmatter.cjs  parse and serialize, id generation, slugify
  watcher.cjs    debounced recursive fs.watch
  config.cjs     config.json in userData
  preload.cjs    the one narrow window.stash API
src/             renderer: React + CodeMirror 6
  App.jsx        tabs, autosave, shortcuts, everything wired together
  components/    title bar, sidebar, tree, editor, panels, search, toasts
  lib/           fuzzy match, variables, diff, relative time, editor setup
scripts/         dev launcher, icon generator
```
